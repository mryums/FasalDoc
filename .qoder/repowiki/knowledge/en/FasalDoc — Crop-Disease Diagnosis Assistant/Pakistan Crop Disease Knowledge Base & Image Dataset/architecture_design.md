The module is organized into two parallel layers. The `dataset/` sub-package contains Python source files that define the authoritative content: `plants.py` holds shared plant metadata (`PLANTS`, `PLANT_SLUGS`, `FOLDER_TO_PLANT`), `healthy_entries.py` provides one bilingual entry per crop for the classifier's 'healthy' class, and `part1_vegetables_cereals.py`, `part2_rice_cotton_chili_onion.py`, `part3_fruits_legume.py` each expose a `DISEASES` list of disease records grouped by crop category. Each record is a dict with fields `plant`, `disease`, `disease_ur`, `aliases`, `type`, `causal_agent`, parallel `description_en/description_ur`, `symptoms_*`, `causes_*`, `treatment_*`, `prevention_*`, plus `image_label_en`, `source`, `source_url`, `confidence`, and `notes`. The `plant_disease_dataset/` directory is the published artifact layer: `crop_knowledge.json` is the machine-readable JSON schema documented in `README.md` (with stable `PL###` plant IDs and `DS###` disease IDs), `crop_knowledge_enhanced.xlsx` is the human-editable master spreadsheet, `image_mapping.csv` maps original photos to canonical `IMG###` ids, and `images/{plant}/{plant}_{disease}_{nn}.{ext}` holds 116 normalised reference photos. A `DATA_QUALITY_REPORT.md` tracks provenance and verification flags. The dependency direction is one-way: the Python `dataset/` sources are the authoring layer that feeds into the static JSON/Excel artifacts consumed at runtime by the website.
